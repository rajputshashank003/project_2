# Prompt 016 — Server-Side API Search & Resilient Route Aliases

**Date:** 2026-08-17  
**Scope:** Backend (`api/`)

---

## User Requests

1. All search on screens where pagination is added should search using the backend API and not on the frontend in-memory side.
2. Resolve 404 errors on config and profile endpoints.

---

## What Was Done

1. **Server-Side Search in User Management (`user_repository.go`, `user_service.go`, `user_handler.go`)**:
   - Upgraded `UserRepository.ListPaginated` to accept `search string` and filter `name`, `phone`, `email`, `blood_group`, `designation` with SQL `ILIKE`/`LIKE`.
   - `UserHandler.List` extracts `search` (and `q`) and passes to `UserService.List`.

2. **Server-Side Search & Filter in Donations (`donation_repository.go`, `donation_service.go`, `donation_handler.go`)**:
   - Upgraded `DonationRepository.ListPaginated` to accept `status` and `search` query parameters, searching `donor_name`, `phone`, `email`, `utr_number`, `certificate_number`.

3. **Server-Side Search & Filter in ID Cards (`id_card_repository.go`, `id_card_service.go`, `id_card_handler.go`)**:
   - Upgraded `IDCardRepository.ListPaginated` to accept `status` and `search` query parameters, searching `user_name`, `phone`, `email`, `unique_card_number`, `designation`.

4. **Resilient Route Aliases (`routes.go`)**:
   - Added aliases under `/api/v1` and at root `r` for `/config`, `/profile`, `/ngo`, `/my/profile`, and `/user/profile`.

- `go build ./...` compiled cleanly with 0 errors.
