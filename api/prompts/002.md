# Prompt 002 — Backend Notice Fixes for Frontend Integration

**Date:** 2026-08-14
**File:** `api/prompts/002.md`

---

## Original Prompt

Part of: "Replace all mock APIs with actual backend APIs" (see `client/Prompts/005.md`).

During the frontend migration the following backend inconsistencies were identified:
1. `CreateNoticeRequest` had no `IsActive` field — notices were always created as `active: true`
2. `PATCH /notices/:id` returned `{data: {message: "Notice updated"}}` — client couldn't use the response
3. `DELETE /notices/:id` returned `{data: {message: "Notice deleted"}}` — inconsistent with other delete endpoints

---

## What We Changed

### `internal/dto/notice_dto.go`
- Added `IsActive *bool \`json:"isActive"\`` to `CreateNoticeRequest`
- Field is optional; defaults to `true` in the service if nil

### `internal/service/notice_service.go`
- `Create()` — reads `IsActive` from DTO with nil-safety:
  ```go
  isActive := true
  if req.IsActive != nil {
      isActive = *req.IsActive
  }
  ```
- `ToggleActive()` — changed signature from `error` to `(*models.Notice, error)`:
  - Calls `repo.ToggleActive()` first, then `repo.FindByID()` to return fresh record
  - This enables the handler to return the full notice object

### `internal/handler/notice_handler.go`
- `Update()` — changed `h.svc.ToggleActive()` call to capture returned notice:
  ```go
  notice, err := h.svc.ToggleActive(id, *req.IsActive)
  ...
  c.JSON(http.StatusOK, gin.H{"data": notice})
  ```
- DELETE handler unchanged — client does optimistic delete so response body not consumed

---

## Response Shape After Fix

| Endpoint | Before | After |
|---|---|---|
| `POST /notices` | `{data: notice}` | `{data: notice}` (no change) |
| `PATCH /notices/:id` | `{data: {message: "Notice updated"}}` | `{data: notice}` (full object) |
| `DELETE /notices/:id` | `{data: {message: "Notice deleted"}}` | `{data: {message: "Notice deleted"}}` (unchanged) |
