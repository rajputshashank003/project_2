# Prompt 012 — Asynchronous Cloudinary Asset Cleanup & BloodGroup Serialization

**Date:** 2026-08-16  
**Scope:** Backend (`api/`)

---

## User Requests

1. Investigate and ensure that whenever any image is deleted anywhere in the repository, it is also deleted from Cloudinary.
2. Fix "Continue to Portal" profile onboarding modal not closing on submit.
3. Fix organization config update API timeout when uploading and saving a new logo.

---

## What Was Done

1. **Cloudinary Asset Deletion Verification**:
   - Verified that Cloudinary asset deletion (`s.cloudinary.Delete(ctx, assetID)`) is actively hooked across all resources:
     - Events (deleting event, removing images during edit, orphan protection)
     - Gallery (deleting photo, upload rollback)
     - Notices (deleting notice, upload rollback)
     - Team Members (replacing photo, clearing slot, removing slot)
     - Org Settings (replacing/removing logo & digital signature)
     - Donations & ID Cards (orphan protection rollback on DB failures)

2. **BloodGroup Model Serialization (`internal/models/user.go`)**:
   - Removed `omitempty` from `BloodGroup string` so that the field is always present in JSON responses, allowing the client `AuthContext` to reliably verify profile completeness.

3. **Asynchronous Asset Deletion on Config Update (`internal/service/ngo_service.go`)**:
   - Moved the deletion of previous logo and signature Cloudinary assets into asynchronous goroutines (`go s.cloudinary.Delete(context.Background(), ...)`).
   - This eliminates sequential waiting for Cloudinary Destroy API calls during the upload request, preventing HTTP timeouts.
