# Prompt 024 — Merge WhatsApp Service into Single API Server

**Date:** 2026-08-18  
**Scope:** Backend (`api/`) & Frontend (`client/`)

---

## User Requests

1. Merge `whatsapp_service` into the main API so the platform runs as a single server process without deploying 2 separate services.
2. Ensure all existing flows (OTP login, donation alerts, ID card notifications, health checks, dev mode) are preserved safely without any breaking changes.

---

## What Was Done

1. **`api/go.mod`**:
   - Added `go.mau.fi/whatsmeow` and `modernc.org/sqlite` (pure Go SQLite driver, zero CGO required) and `github.com/skip2/go-qrcode`.

2. **`api/internal/wa/` Package**:
   - `store.go`: SQLite session persistence (`store/whatsapp.db`).
   - `client.go`: `WAClient` connection lifecycle and QR state manager.
   - `sender.go`: `WAClient.Send(phone, message)`.
   - `qr.go`: `qrToPNG` helper.

3. **Service & Health Refactoring**:
   - `internal/service/whatsapp_local_service.go`: Uses in-memory `waClient.Send()` with dev mode fallback.
   - `internal/service/health_service.go`: Probes in-memory `waClient.Status()` directly.
   - `internal/config/config.go`: Added `WhatsAppDBPath` (default `"store/whatsapp.db"`).

4. **Handlers, Routes & Main Entrypoint**:
   - `internal/handler/whatsapp_handler.go`: Created `WhatsAppHandler` serving `/qr` and `/api/v1/whatsapp/status`.
   - `internal/routes/routes.go`: Registered `/qr`, `/whatsapp/qr`, `/api/v1/whatsapp/status`, `/health/whatsapp`.
   - `cmd/server/main.go`: Initialized WhatsApp store and client on startup, with clean disconnect on SIGINT/SIGTERM.

5. **Frontend Navbar (`client/src/components/Navbar/index.tsx`)**:
   - Dynamically resolves the "Verify WhatsApp" QR modal URL directly to `{API_BASE_URL}/qr` or `http://localhost:3000/qr`.
