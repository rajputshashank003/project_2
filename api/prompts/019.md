# Prompt 019 — OOP HealthService & WhatsApp 13-Minute Keep-Alive Worker

**Date:** 2026-08-17  
**Scope:** Backend (`api/`)

---

## User Requests

1. Create a health endpoint which calls the WhatsApp service `/api/health` after every 13 minutes.
2. Implement as a structured class adhering to OOP principles.

---

## What Was Done

1. **Created `HealthService` (`api/internal/service/health_service.go`)**:
   - Encapsulates database ping, WhatsApp microservice HTTP health probing, latency calculation, and the 13-minute keep-alive worker loop.
   - Methods:
     - `CheckDatabase(ctx)`: Validates PostgreSQL database connectivity.
     - `CheckWhatsAppService(ctx)`: Performs an HTTP GET request to `{whatsAppURL}/api/health` with a 10s timeout.
     - `GetOverallHealth(ctx)`: Combines DB and WhatsApp microservice status into an overall readiness report.
     - `StartKeepAliveWorker(ctx)`: Runs an anti-sleep keep-alive loop every 13 minutes, pinging the WhatsApp microservice and logging via Zerolog.

2. **Updated `HealthHandler` (`api/internal/handler/health_handler.go`)**:
   - `Liveness`: `GET /healthz`, `GET /health`, `GET /api/health` (HTTP 200 OK).
   - `Readiness`: `GET /readyz` (DB + WhatsApp status report).
   - `WhatsAppHealth`: `GET /health/whatsapp` & `GET /api/v1/health/whatsapp` (Dedicated WhatsApp health probe).

3. **Updated Server & Routes (`api/internal/routes/routes.go`, `api/cmd/server/main.go`)**:
   - Instantiated `healthSvc` and launched `go healthSvc.StartKeepAliveWorker(ctx)` tied to graceful shutdown.
   - Registered endpoints at root and `/api/v1`.
