# Prompt 008 — Fix Unique Constraint Collision on Pending/Unapproved Donations and ID Cards

**Date:** 2026-08-16  
**Scope:** Backend (`api/`)

---

## User Request

> "donation: db create failed: ERROR: duplicate key value violates unique constraint "donations_certificate_number_key" (SQLSTATE 23505) not able to submit donate"

---

## Root Cause
- In `models/donation.go` and `models/id_card.go`, `CertificateNumber` and `UniqueCardNumber` were declared as plain `string` fields.
- When creating pending or rejected records, GORM inserted empty strings `""` instead of SQL `NULL`.
- PostgreSQL unique constraints (`UNIQUE(certificate_number)` and `UNIQUE(unique_card_number)`) allow unlimited `NULL` values, but only a single empty string `""`.
- The insertion of a second record without an assigned certificate or card number collided with the first empty string and threw SQLSTATE 23505.

---

## What Was Done

### 1. Database Migration (`000014_fix_unique_certificate_and_card_numbers`)
- `000014_fix_unique_certificate_and_card_numbers.up.sql`:
  - Converted existing empty strings `''` to `NULL` for `donations.certificate_number`, `donations.certificate_url`, `donations.rejection_reason`, `donations.utr_number`, `donations.reviewed_by`.
  - Converted existing empty strings `''` to `NULL` for `id_cards.unique_card_number`, `id_cards.rejection_reason`, `id_cards.reviewed_by`.
- `000014_fix_unique_certificate_and_card_numbers.down.sql`:
  - No-op rollback query.

### 2. Model Pointer Types
- `internal/models/donation.go`:
  - Converted `CertificateNumber`, `CertificateURL`, `RejectionReason`, `UTRNumber`, `ReviewedBy` to `*string` pointer types.
- `internal/models/id_card.go`:
  - Converted `UniqueCardNumber`, `RejectionReason`, `ReviewedBy` to `*string` pointer types.

### 3. Service Layer
- `internal/service/donation_service.go`:
  - Set `utrPtr *string` conditionally when `req.UTRNumber != ""`.
