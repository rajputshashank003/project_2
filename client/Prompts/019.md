# Prompt 019 — Server-Side API Search & Filter on Paginated Lists

**Date:** 2026-08-17  
**Scope:** Frontend (`client/`)

---

## User Requests

1. All search on screens where pagination is added should search using the backend API and not on the frontend in-memory side.
2. Resolve 404 errors on config and profile endpoints.

---

## What Was Done

1. **User Management Screen (`users.ts` & `useAdminUsers.ts`)**:
   - `getUsers` accepts `search?: string` and passes to `GET /users?search=...`.
   - `useAdminUsers` debounces user input by 300ms, triggering backend query and resetting to page 1.
   - Removed local in-memory filtering so full database results and page totals are accurately reflected.

2. **Donation Requests Screen (`donations.ts` & `useAdminRequestDonation.ts`)**:
   - `getDonations` accepts `status?: string` and `search?: string`, querying `GET /donations?status=...&search=...`.
   - `useAdminRequestDonation` debounces search input by 300ms and filters via API.

3. **ID Card Requests Screen (`id_cards.ts` & `useAdminRequestIdCard.ts`)**:
   - `getIdCardRequests` accepts `status?: string` and `search?: string`.
   - `useAdminRequestIdCard` queries status filters through the API on change.

---

- `npm run build` compiled cleanly in 289ms with 0 errors.
