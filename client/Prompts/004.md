## Architectural & Implementation Details

### 1. Portal-Based `MenuDropdown` Component (`src/components/MenuDropdown/index.tsx`)
- **Body Portal Rendering (`createPortal`)**: Renders both the full-screen backdrop overlay (`fixed inset-0 z-50 bg-slate-900/40 backdrop-blur-sm`) and floating menu content directly under `document.body` via React `createPortal`.
- **Breaking Stacking Contexts**: By rendering outside the sticky `<header>` parent container, the backdrop overlay is not trapped inside the header's CSS `backdrop-blur-sm` stacking context. It covers **100% of the entire page viewport**, blurring and disabling interaction across the entire screen.
- **Outside Click Dismissal**: Added `onClick={onClose}` handler to the backdrop overlay layer so clicking anywhere outside the open menu immediately closes it.
- **Keyboard Escape Support**: Added an `Escape` key event listener so pressing `Esc` dismisses the open menu immediately.
- **React.Fragment**: Wrapped backdrop and content elements in `<React.Fragment>` syntax exclusively.

### 2. Navbar Integration (`src/components/Navbar/index.tsx`)
- Refactored the Admin navigation dropdown and mobile menu drawer to consume `MenuDropdown` and backdrop overlay.
- Ensures all dropdown navigation links ("Donation Requests", "ID Card Requests", "Users", "Noticeboard", "Gallery", "Events", "Team Members", "Organization Settings") display cleanly over the backdrop overlay with outside-click dismissal.

## Followup Bug Fix
- **Issue**: Initial implementation positioned the overlay inside the header, causing CSS stacking context trapping where only the header bar blurred instead of the full page screen.
- **Fix**: Used `createPortal(..., document.body)` in `MenuDropdown` with dynamic `getBoundingClientRect()` calculation to render the full-screen backdrop overlay over 100% of the viewport.
