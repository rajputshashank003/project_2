# Prompt 010 — Stop Login / Phone Whitelist & Maintenance Mode

**Date:** 2026-08-16  
**Scope:** Frontend (`client/`)

---

## User Request

> "create a stop login env variable in fe side if it contains phonenumbers like 1242342, 4124342, 2423423 then only tehse number are allowed to login, for other show toast feature under maintainance"

---

## What Was Done

1. **Environment Variable Configuration (`.env`, `.env.example`)**:
   - Added `VITE_STOP_LOGIN=""` with explanatory comment.
   - Accepts a comma-separated list of allowed phone numbers (e.g. `VITE_STOP_LOGIN="1242342, 4124342, 2423423"`).
   - If empty or set to `"false"`, login is open to everyone.

2. **Validation Helper (`utils/helpers.ts`)**:
   - Added `isLoginAllowedForPhone(phone: string): boolean`.
   - Normalizes both the input phone and env whitelist by stripping non-digit characters and checking exact or 10-digit suffix matches.

3. **Login Hook Enforcement (`screens/Login/useLogin.ts`)**:
   - In `handleSendOtp` and `handleResendOtp`: checks `isLoginAllowedForPhone(cleaned)`.
   - If blocked: immediately triggers `toast.error('Feature under maintenance')` and halts execution without sending an API request.

4. **Login Screen UI & Alignment Revamp (`Login.tsx`, `components/LoginSteps.tsx`)**:
   - Removed awkward stacked duplicate icon badges (outer Leaf box + inner Phone box).
   - Added unified, elegant NGO branding header displaying the organization's real logo or badge + name pill.
   - Restructured Phone input into an integrated container with flag + "+91" prefix divider and smooth focus rings.
   - Aligned typography, spacing, CTA button states, and step indicator for a polished, premium aesthetic.
   - Made bottom verification trust note responsive (`text-[11px] sm:text-xs whitespace-nowrap`) so it remains strictly on a single line on all mobile screens without wrapping.
