## What We Did

### Phase 1 — Foundation: Fix Axios Utils & Error Handling
- Fixed error envelope parsing: `axiosErr.response?.data?.message` → `axiosErr.response?.data?.error?.message` (Bug #1)
- Fixed `BASE_URL` to include `/v1` path prefix (Bug #2)
- Added `unwrap<T>()` helper to extract `.data` from `{data: T}` backend envelope
- Added `PaginatedResponse<T>` interface for paginated list responses
- Added `ApiResponse<T>` interface for single-item responses
- Fixed `VITE_API_BASE_URL` in `.env.example`

### Phase 2 — TypeScript Types
Updated 5 type files to match backend model JSON shapes:
- `donation.ts` → added `certificateNumber?`
- `id_card.ts` → added `validityYears?` to `IdCard` + `UpdateIdCardStatusPayload`
- `ngo.ts` → added `id?` + `updatedAt?`
- `event.ts` → added `eventId?` to `EventImage`
- `notice.ts` → kept `isActive` in `CreateNoticePayload` (now supported by backend after Phase 7)

### Phase 3 — Replace All API Functions (9 files)
Removed all `USE_MOCK` constants, mock imports, `_mock_store` arrays. All functions now:
- Call the real backend via `axiosInstance`
- Unwrap the `{data: T}` envelope before returning
- Return `PaginatedResponse<T>` for all list endpoints (donations, id-cards, notices, gallery, events, users)
- Non-paginated: team_members (`getTeamMembers` returns `TeamMember[]` unwrapped)
- Added `Idempotency-Key: crypto.randomUUID()` header to `createDonation` and `createIdCardRequest`
- Fixed `updateNgoConfig` field name mapping: `logoUrl`→`logoBase64`, `signatureUrl`→`signatureBase64` (Bug #9)
- Added `promoteUser()` and `demoteUser()` functions to `users.ts`

### Phase 4 — Update Screen Hooks (14 files)

- `useAdminRequestIdCard.ts` — removed `generateCardNumber()` (Bug #5); extract `.data`; use returned `IdCard`
- `useCertificateView.ts` — removed `MOCK_DONATION`; uses real `data.certificateNumber` from backend (Bug #6)
- `useIDCardView.ts` — removed `MOCK_ID_CARD`; added `notFound` state
- `useDonate.ts` — removed inner catch fallback
- `useIDGenerate.ts` — removed inner catch fallback
- `useHome.ts` — extract `.data` from `PaginatedResponse` for notices and gallery

## Code Rules Followed
- camelCase for all variables (matching existing codebase convention)
- No flow/logic changes — only data source swap (mock → backend)
- All API functions unwrap the backend `{data: T}` envelope before returning
- Paginated endpoints use `PaginatedResponse<T>` with `.data` extraction in hooks
- Idempotency-Key headers on `POST /donations` and `POST /id-cards`
- Error handling: `axiosInstance` shows toast on all errors; hooks use empty `catch {}` to avoid double-toasting
- Optimistic updates with revert-on-failure for toggle and delete operations
- `<React.Fragment>` (not `<>`) as per existing code rules
